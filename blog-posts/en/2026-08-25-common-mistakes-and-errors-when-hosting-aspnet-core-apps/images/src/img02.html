Verifying the runtime on the server
Run dotnet --list-runtimes on the server after installing the Hosting Bundle.
Administrator: Command Prompt — WEBSRV01
C:\> dotnet --list-runtimes   Microsoft.AspNetCore.App 8.0.28 [C:\Program Files\dotnet\shared\Microsoft.AspNetCore.App] Microsoft.AspNetCore.App 9.0.14 [C:\Program Files\dotnet\shared\Microsoft.AspNetCore.App] Microsoft.AspNetCore.App 10.0.9 [C:\Program Files\dotnet\shared\Microsoft.AspNetCore.App] Microsoft.NETCore.App 8.0.28 [C:\Program Files\dotnet\shared\Microsoft.NETCore.App] Microsoft.NETCore.App 9.0.14 [C:\Program Files\dotnet\shared\Microsoft.NETCore.App] Microsoft.NETCore.App 10.0.9 [C:\Program Files\dotnet\shared\Microsoft.NETCore.App] Microsoft.WindowsDesktop.App 10.0.9 [C:\Program Files\dotnet\shared\Microsoft.WindowsDesktop.App]
The highlighted Microsoft.AspNetCore.App entries are the ones that matter. If you only see Microsoft.NETCore.App, the standalone .NET Runtime is installed but the ASP.NET Core Hosting Bundle is not — and IIS will fail with 500.19 or 500.31. The listed version must also be equal to or newer than your target framework.
